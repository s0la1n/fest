#### 2. Проверка юзабилити

- **Меню:** Есть главное меню в шапке (Navigation): Главная, О нас, Турнир, Косплей, Расписание; для авторизованных — Голосование, Магазин, Профиль, Баланс; для организаторов — разделы «Орг. турнир», «Орг. косплей»; для админа — Статистика, Админ-панель. Ссылки ведут на указанные маршруты.
- **Мобильная версия:** Реализовано адаптивное меню (бургер), контент подстраивается под ширину экрана. Для отчёта можно указать: «Проверка на мобильных: сужение окна браузера показывает корректное отображение и рабочее меню».
- **Кнопка «Наверх»:** На момент аудита глобальной кнопки «Наверх» может не быть — рекомендуется добавить для длинных страниц (расписание, косплей, магазин).
- **Заголовки разделов:** На страницах используются понятные заголовки (h1, h2), семантика выдержана.

#### 3. Фиксация в отчёте (формулировка для отчёта)

**«На момент начала практики сайт имеет следующую структуру:** главная страница, разделы «О фестивале», «Турниры», «Косплей», «Расписание», «Контакты»; разделы для авторизованных пользователей: «Магазин», «Карточки маскотов», «Баланс», «Ставки», «Профиль», «Голосование»; разделы покупки билета и входа; разделы для организаторов (турнир, косплей) и админ-панель. ### Задание 6: Дубли страниц и битые ссылки (локально)

**Рекомендуемые действия:**

### Задание 8: Alt и Title для изображений

**Текущее состояние по проекту:**

- На сайте используются теги `<img>` и компонент `next/image` с атрибутом `alt`.
- Примеры: логотип — `alt="Игровой Лабиринт - логотип"`; косплей — `alt="Косплей конкурс 2026"`, `alt="${cosplayer.character} косплей от ${cosplayer.name}"`; магазин — `alt={p.name}`; карточки — `alt={c.name}`; спонсоры — `alt={\`Логотип ${sponsor.name}\`}`.
- Часть изображений имеет осмысленный alt; у части (например, в голосовании) встречается пустой `alt=""` — рекомендуется заменить на краткое описание с ключевыми словами.

**Рекомендации:**

- Для каждого `<img>` и `next/image` прописать `alt="описание с ключевыми словами"`.
- По желанию добавить `title="подсказка при наведении"` для важных изображений.

**Пример для отчёта:**  
«Прописаны (или доработаны) alt-тексты для изображений сайта. Использованы ключевые слова: фестиваль, косплей, турнир, мерч, логотип спонсора и т.д. Это улучшит ранжирование сайта в поиске по картинкам и доступность.»

### Задание 11: Файл robots.txt

**Выполнено:** файл `robots.txt` создан и размещён в корне фронтенда: `next-frontend/public/robots.txt`.

**Содержимое (шаблон):**

```
User-agent: *
Disallow: /admin/
Disallow: /organizer/
Disallow: /api/

Host: https://твойбудущийсайт.ru
Sitemap: https://твойбудущийсайт.ru/sitemap.xml
```

После размещения на хостинге нужно заменить `твойбудущийсайт.ru` на реальный домен. В Next.js файлы из `public/` доступны по корню сайта, т.е. `https://домен.ru/robots.txt`.

**Для отчёта:** «Создан файл robots.txt в корне сайта. Запрещена индексация служебных разделов (/admin/, /organizer/, /api/). Указаны директива Host и путь к sitemap.xml для последующей настройки после публикации.»

### Задание 9: База данных (если есть)

**Состояние проекта:** сайт использует БД: **MySQL** (или MariaDB), бэкенд — **Laravel** (каталог `laravel-backend`).

**Экспорт базы для переноса на хостинг:**

1. **Через командную строку (Laravel):**
   ```bash
   cd laravel-backend
   php artisan db:export backup.sql
   ```
   (если такой команды нет — использовать mysqldump ниже.)

2. **Через mysqldump:**
   ```bash
   mysqldump -u пользователь -p имя_базы > backup.sql
   ```

3. **Через phpMyAdmin (если установлен):** вкладка «Экспорт» → выбрать базу → экспорт в SQL-файл, сохранить файл для загрузки на хостинг.

**Для отчёта:** «Сайт использует базу данных MySQL (Laravel). Экспорт выполнен в SQL-файл (через mysqldump / phpMyAdmin / artisan) и сохранён для загрузки на хостинг при размещении.»
